# 乱翻（信息流）推荐算法

> 「乱翻」是上下滑动看「书籍解读短视频」的信息流页（`app/flip/page.tsx`）。本文说明：给用户看哪些书的视频、按什么顺序、刷到底再给什么。
>
> 主要实现：`lib/api.ts`（取池 + 分页 `flipPool`/`getFlip`）、`lib/server/flipfeed.ts`（个性化日更生成器）、`app/api/cron/flip-feed/route.ts`（Cron 入口）、`app/flip/page.tsx`（前端加载/虚拟化）。

---

## 一句话总览
**登录用户看 AI 每日为你定制的书单，游客看「最新有视频」的书；第一屏按推荐序，越往后刷越随机、不重样。**

---

## 一、整体两层

```
用户打开/下滑乱翻
        │
        ▼
   getFlip(seenIds)            ← lib/api.ts
        │
   ┌────┴─────────────────────────┐
   │ flipPool()  取「书池」         │
   │  ├─ 登录：读 flip_feed（AI日更）│
   │  └─ 游客/无feed：最新有视频50本 │
   └────┬─────────────────────────┘
        │
   首屏(seenIds 为空) → 按池原序返回（保住个性化排序）
   续拉(已看过若干)   → 随机打乱 + 跨轮去相邻重复
```

- **缓存**：`flipPool` 结果按 uid 缓存 5 分钟（`lib/api.ts`，`flipPoolCache`）。
- **过滤**：池子里只放 `has_video=true` 且确实有 `video_url` 的书（坏数据护栏）。

---

## 二、个性化书单怎么生成（核心）

每天**北京时间 04:00**，Vercel Cron 调 `/api/cron/flip-feed` → `generateFlipFeeds()`（`lib/server/flipfeed.ts`），为每位读者生成 ≤50 本「猜你想读」写入 `flip_feed` 表。

### 2.1 给每位读者采集「画像信号」（`collectSignals`）

| 信号 | 取什么 | 作用 |
|---|---|---|
| **已读完** | 文字 `pct≥100` 或 音视频真实覆盖 `played≥0.9` | **排除**，不再推 |
| **在读** | 有任何进度、未读完 | **置顶**，放最前 |
| **收藏** | `favorites` 表书 id | 喂 AI 当兴趣依据 |
| **最近笔记** | `notes` 最近 8 条划线/笔记摘录 | 喂 AI |
| **书评** | `reviews` 最近 5 条要点（星级+内容） | 喂 AI |
| **与小涤的对话** | `chat_sessions` 最近用户消息 + 压缩摘要 | 喂 AI（反映兴趣） |
| **长期记忆（T7）** | `user_memory` 的四维：**阅读偏好 / 兴趣主题 / 身份画像 / 近期关注** | 喂 AI，**权重最高**（系统提炼的长期口味，比原始聊天更准更省 token） |

> 「长期记忆」信号于 2026-06-28 接入：和「智学小涤记得你」用的是同一份 `user_memory`——记忆不只用来对话，也用来给你推书。

### 2.2 排序四步（每位读者）

1. **候选池** = 所有「有视频」的书，按最新入库排，最多 `CANDIDATE_CAP=120` 本送 AI；
2. **排除已读完**：从候选去掉 `done` 集合；
3. **在读置顶**：把 `reading` 的书提到最前；
4. **AI 排其余**（`rankByLLM`）：剩余候选 + 读者画像，发给 MiniMax-M3，让它**按「这位读者会感兴趣的程度」从高到低排序**。

最终书单 = `[在读] + [AI 排好的] + [超出120的尾巴按默认序]`，取前 `FEED_SIZE=50` 本，写入 `flip_feed`。

### 2.3 AI 实际收到的指令

- **System**：「你是图书推荐排序引擎。把候选书按『这位读者会感兴趣的程度』从高到低排序。只输出 JSON 字符串数组（候选书的 id），不要输出任何其他文字。只能使用候选列表中的 id，不要遗漏、不要编造。」
- **User**：`[读者画像（含长期记忆/收藏/已读/在读/笔记/书评/对话）]` + `[候选书列表（id/书名/标签/概要）]` → 输出排序后的 id 数组。
- 参数：`temperature=0.3`、`maxTokens=4096`、`timeoutMs=20s`。

### 2.4 兜底链（保证日更不挂）

| 情况 | 兜底 |
|---|---|
| AI 调用失败 / 返回无法解析 | 退回「最新入库」默认序（`llmFallback` 计数） |
| AI 漏排了某些候选 | 漏的补在尾部，保证全覆盖 |
| **全新用户**（零信号：没收藏/读/笔记/书评/对话/记忆） | **不写行** → 前端 `getFlip` 读不到 → 回退「最新有视频 50 本」 |
| 馆里还没有带视频的书 | 直接返回空（前端不渲染） |

## 三、翻页与防重复（`getFlip`，`lib/api.ts`）

- **首屏**（`seenIds` 为空）：按池原序返回 → 个性化排序生效；
- **续拉**（滑到倒数第 2 本触发）：
  - **Fisher-Yates 随机洗牌**（每次顺序都不同，防审美疲劳）；
  - **跨轮去相邻重复**：上一轮最后一本 == 本轮第一本则交换（Bug#21）；
  - 给每本加唯一后缀 `__f{已看数}_{封面种子}`，防 React key 冲突。
- **前端虚拟化**（`app/flip/page.tsx`）：3 个 `<video>` 元素复用池（`SLOTS=3`，当前 ±1 预载）、当前 ±2 渲染窗口。

## 四、数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| `flip_feed` | `user_id, gen_date, book_ids[]` | 每用户每天一行的个性化书单；`onConflict: user_id,gen_date` |
| `books` | `has_video, video_url, shelved_at` | 候选来源；回退按 `shelved_at desc` |
| `user_memory` | `identity, reading_pref, interests, recent_focus`… | T7 长期记忆，画像信号 |

## 五、工程纪律（生成器）

- **分页拉全**：所有正确性查询循环 `range` 取完（PostgREST 默认 1000 行**静默截断**，否则「已读完」集不全 → 误推已读的书）；
- **按批生成、按批落库**：`USER_BATCH=24` 人/批、批内 `CONCURRENCY=4` 并发跑 AI；
- **时间预算 + 断点续做**：`TIME_BUDGET_MS=50s`（route `maxDuration=60s`），超时被掐时已落库的批次保留，下次调用从断点继续（幂等：跳过当天已有的用户）；`?force=1` 强制重生成（测试用）；
- **鉴权**：Vercel 带 `Authorization: Bearer $CRON_SECRET`。

## 六、现状与局限

- **书太少时看不出效果**：当前馆藏仅个位数书、有视频的更少，候选不足，「画像 + AI 排序」基本施展不开；书多到几十上百本才显「千人千面」。
- **是「每日定时生成的固定书单」**，不是「刚看完一本就实时调整」的实时推荐（实时推荐更重，现阶段未做）。
- **回退路径（游客/无 feed）未过滤已读完**：个性化 feed 在生成时已排除已读，但游客/回退取「最新 50 本」时不过滤已读完（书少时影响很小，可按需补）。

## 七、关键参数速查

| 参数 | 值 | 位置 |
|---|---|---|
| 生成时机 | 每天北京 04:00 | vercel.json crons |
| feed 容量 | 50 本 | `FEED_SIZE` |
| 送 AI 候选上限 | 120 本 | `CANDIDATE_CAP` |
| 用户批大小 / 批内并发 | 24 / 4 | `USER_BATCH` / `CONCURRENCY` |
| 生成时间预算 | 50s | `TIME_BUDGET_MS` |
| 池缓存 | 5 分钟 | `flipPoolCache` |
| 回退书单容量 | 最新有视频 50 本 | `flipPool` 回退路径 |
| 视频复用池 / 渲染窗口 | 3 / ±2 | `SLOTS` / FlipOverlay |
