# 阅读时长 / 进度 / 覆盖率 统计算法

> 说明 App 里和「读了多久、读到哪、读完没」相关的三套**互相独立**的口径，以及 2026-06-28 修复的「音视频覆盖率虚高」根因。
>
> 主要实现：`lib/useReadingClock.ts`（时长）、`components/library/Players.tsx` + `app/flip/page.tsx`（上报覆盖区间）、`lib/store.ts`（覆盖率并集 + 持久化）、`lib/supabase/userdata.ts`（读写云端）。

---

## 一、三套口径（别混）

| 口径 | 字段 | 含义 | 云端表 |
|---|---|---|---|
| **阅读时长** | `readSeconds` | 真实播放/阅读的**墙钟秒数之和**（音视频+文字） | `profiles.read_seconds` |
| **音视频覆盖率** | `mediaPlayed` / `mediaCovered` | 真实播过的**内容占比**（判「已读完」） | `media_progress.played` / `covered` |
| **续播位置** | `mediaProgress`（音视频）/ `progress.pct`（文字） | 下次从哪接着 | `media_progress.position` / `text_progress` |

> 关键：**「时长」和「覆盖率」是两回事**。时长 = 你花了多少时间；覆盖率 = 你把内容看了多少**不重复**的比例。反复重播同一段：时长会涨（确实花了时间），但覆盖率不该涨（还是那点内容）。

---

## 二、阅读时长 `readSeconds`（`useReadingClock`）

**= 音视频播放时长 + 文字稿阅读时长**，逻辑简单可靠：

- 当 `active` 且**页面可见**时，墙钟**每秒 +1**；
- 每攒满 30 秒落一次账（`addReadSeconds` → 云端**增量 RPC**，多设备不互相覆盖）；切后台 / 退出 / 卸载补写零头。

各处 `active` 条件：
| 场景 | active |
|---|---|
| 详情页视频 / 音频 | `playing`（仅播放时） |
| 乱翻视频 | `playing && !出错` |
| 文字阅读器 | `!!cur`（打开阅读器有章节即计） |

> 已知小瑕疵：文字稿是「打开阅读器(可见)就计」，挂机会偏高（音视频是「仅播放时计」更严谨）；受「页面可见」约束，切后台即停。**这部分逻辑本身没有 bug。**

---

## 三、音视频覆盖率 `played`（2026-06-28 根治）

判「已读完」靠它：`played ≥ 0.9 → 已读完`。

### 3.1 旧算法的 bug（已修）
旧实现把覆盖率当「累计量」算：
- 详情页：`played = base(上次存的) + 本会话播放并集 / 时长` → **跨会话重播同一段会反复加到 base 上**；
- 乱翻：`playedSec += d` 直接累加秒数，**连并集都没做**，会话内重播就翻倍。

后果：**反复从头重播一小段，played 一路虚涨到 0.9 → 误判已读完**。
> 实锤：用户「涤生」总时长仅 40 分钟，7 本音频真实合计 184 分钟，却因反复重开（position 全贴开头）被判 7 本全读完。

### 3.2 新算法（区间并集 + 持久化）
**覆盖率 = 真实播过的「归一化区间(0~1)并集」总长**，区间集合持久化到云端：

1. 播放时，连续正常推进（增量 `0 < d < 1.5s`）才上报这一段：`addCoveredRegion(书, lastT/dur, cur/dur)`；拖动/快进/loop 回卷（d 不在 0~1.5）**不上报**；
2. `store.addCoveredRegion` 把新区间**合并进并集**（`mergeRegions`：排序+合并重叠/相邻），`played = 并集总长`；
3. **重播已覆盖的段 → 并集不增长 → played 不虚涨**（根治）；
4. 区间集合存 `media_progress.covered`（jsonb），跨会话/跨设备恢复，`played` 由 `covered` 派生。

详情页（`Players.trackPlayed`）和乱翻（`flip.onSlotTime`）**都只负责上报区间**，并集与持久化统一在 store——一处修复，两端生效。

## 四、续播位置 `position`（音视频）

- 存 `cur/dur`（0~1 分数）；**音↔视、乱翻↔详情按书共享**（同一 `book.id`，内容一致所以共享）；
- **仅「自然前进播放」时写**（`0<d<1.5`）：拖动跳变 / loop 回卷不落，防把共享位置污染回 0 或乱跳。

---

## 五、拖动不污染统计

拖动进度条 / ±15 秒 → 调 `seekReset()`（`lastT=null`）→ 下一帧的大跳变 `d` 不满足 `0<d<1.5` → **既不计入覆盖区间、也不写续播位置**。所以「拖到结尾」不会被算成读完。

---

## 六、文字稿进度 `pct`（独立于音视频）

- 全书进度 = `(已读完章节数 + 当前章滚动比例) / 总章数`，最高 99，全部章读完才 100；
- 章「读完」= 滚到底（≥95%）或 内容不足一屏；
- `pct ≥ 100 → 文字已读完`。与音视频覆盖率**互不影响**（不同表）。

---

## 七、「已读 / 进行中」判定（聚合口径）

- **一本书已读完** = 文字 `pct≥100` **或** 音视频 `played≥0.9`（任一即算）；
- **进行中** = 文字或音视频任一「0<进度<100」正在读（按书去重，0% 不算）；
- 计数按**书**去重，不重复计。

---

## 八、数据模型 & 迁移

`media_progress` 表：`user_id | book_id | position | played | covered(jsonb)`。

**迁移（本次新增）：**
```sql
-- 1) 新增覆盖区间列（必须，否则播放写库会报「列不存在」）
ALTER TABLE media_progress ADD COLUMN IF NOT EXISTS covered jsonb NOT NULL DEFAULT '[]'::jsonb;

-- 2) 清掉旧算法虚高的脏数据，让新区间算法从头正确统计（dev 建议执行；生产慎用）
UPDATE media_progress SET played = 0, covered = '[]'::jsonb;
UPDATE reading_history SET progress = 0 WHERE mode_category = 'av';
```
- 加列后，旧行 `covered=[]` → 加载时 `played` 派生为 0，**之前虚高的「已读完」自动纠正**；
- 第 2 段把云端 `played` / 媒体历史进度也清零（否则服务端（乱翻日更/智学）仍读到旧虚高值）。

> 服务端口径一致：`flipfeed.ts` / `agent.ts` 判「音视频已读完」也是 `played≥0.9`，迁移清零后同步纠正。
