# 决策记录 ——「全面优化任务书」自主执行（2026-06-11）

> 任务书要求全程自主迭代、零人工介入，所有自主拍板的决策逐条记录于此（决策点 / 备选方案 / 最终选择 / 理由）。

## T5 · 模型与思考链

**1. M3 模型确切 ID 的确认方式**
- 备选：A. 按文档惯例猜测（abab-m3 等）；B. 写最小脚本实测探活。
- 选择：B。`scripts/probe-models.mjs` 实测 `MiniMax-M3` 可用（abab-m3 返回 unknown model），另经 GET /v1/models 文档双确认。证据：evidence/T5/m3-format-probe.md。

**2. 思考链回灌的承载形态**
- 备选：A. 独立 reasoning 字段（OpenAI o 系风格）；B. content 内联 `<think>` 原样保留。
- 选择：B。实测 M3 思考段为 content 内联 `<think>`（无独立字段），把含 `<think>` 的 assistant 消息原样回灌被 API 接受且第二轮思考能延续第一轮工具所得。面向用户与回灌必须两路：streamChat 改三路事件（delta 剥思考 / think 思考增量 / tool_calls+rawContent 原文）。

**3. MAX_ROUNDS 工具循环上限**
- 备选：维持 5 / 上调 8 / 不设限。
- 选择：8。M3 的 toc→多章细读→出卡是常态路径，5 轮经常掐在半路；T10 联网搜索上线后还会叠加轮次；仍保留护栏防失控。

**4. 压缩产物长度口径**
- 备选：A. 每次产物必须≈5K tokens；B. 上限放宽到约 5K，产物长短由源信息量决定。
- 选择：B。「500K 触发→压到 5K」语义是上限放宽（原 1500 tokens 压得太猛）；摘要指令 3500 字以内 + maxTokens 8192 + 存储上限 16000 字。源仅 3699 字时压出约 1000 字属合理保真，不凑长度。

## T4 · 单一会话

**5. 老数据迁移方案**
- 备选：A. 按时间顺序合并为单一会话流；B. 仅取最近会话、其余归档。
- 选择：A（任务书推荐）。51 行→每用户一条 main，128/46/6 条逐用户核对一致零丢失；备份表 `chat_sessions_backup_t4` 保留全量可回滚。旧逐会话压缩摘要不拼接（语义重叠），置空由压缩器对合并流重新生成。

**6. 旧客户端兼容方式**
- 选择：服务端对登录用户一律强制 sessionId='main'（忽略请求值），旧客户端缓存的 sess-xxx 不再产生分叉，零迁移成本。

**7. 跨设备并发写策略（已知限制）**
- 现状：persist 以消息级并集合并（按 id 去重 + id 时间戳稳定排序）后整段 upsert；两设备同时聊天仍可能丢极端并发的尾部消息。
- 取舍：完美解决需服务端 append 式 API（协议级改造），单人多设备同时打字属边缘场景，记入后续改进。

**8. 单一会话请求体（已知限制）**
- 现状：前端发送全量历史（压缩 until 的裁剪以「完整请求口径数组」为前提，客户端贸然截断会让 until 切片错位、制造上下文黑洞）。
- 取舍：当前最大用户 128 条（约 100KB），可接受；窗口化需要「服务端自取历史 + regenerate 显式参数」的协议改造，记入后续改进。

## T3 · 卡片失配

**9. 三层之外的服务端兜底设计**
- 备选：A. 仅靠 system 约束与工具事件加固；B. 增加收尾失配检测 + 补救轮。
- 选择：B。实测 M3 在「历史里推荐过同一本书」时仍概率性只说不调。三类信号触发补救（承诺语境正则 / 细读过章节却无引用卡 / 推荐意图+提及馆藏书名却零卡片），补救轮只许出卡不许说话；泛匹配 /卡片/ 会被「卡片笔记法」误触发，故用承诺语境正则。

**10. 卡片事件直带展示数据**
- 选择：cites 事件直带书名/章题/snippet/封面（原前端为 60 字摘要拉整本书正文，数百 KB）；recs 带 {id,title} 作降级保底。一举解决性能黑洞与「前端拉数据失败丢卡」失配源。

## T8 · 水波纹与思考包装

**11. 思考包装的加工方式**
- 备选：A. 轻量模型即时摘要（每段思考一次调用，延迟+成本）；B. 规则提取（信号词→精修短句池）。
- 选择：B。零延迟零成本，思考期间提示能即时跟上；硬约束（无工具名/ID/技术细节、≤20 字、第一人称）由短句池天然保证。实测序列样本：「正在核对原文出处→翻开《被讨厌的勇气》→细读第2章→整理原文出处」。

**12. 扫光动效的合成属性实现**
- 备选：A. background-position 文字裁切（视觉最佳但触发 paint）；B. 双层文字+滑动窗口纯 transform。
- 选择：B。窗口位移与窗内文字按 -0.36 比例精确互补（百分比基准换算），文字视觉静止、高光窗掠过，keyframes 仅 transform（代码层核对通过），满足 60fps 硬要求。

## T6 · 语音输入

**13. 识别引擎选型（任务书前提与现实不符，以实际为准）**
- 事实核查：MiniMax 无任何 ASR 服务（官方文档索引零条目、4 个候选端点 404、chat 多模态音频输入被忽略——三层穷尽，evidence/T6/asr-investigation.md）。
- 备选：A. 浏览器原生 SpeechRecognition；B. 第三方 ASR（阿里云/讯飞，需用户开通并提供新密钥）；C. 放弃语音。
- 选择：A。零新增密钥（B 违背零人工介入与秘钥安全）；iOS Safari 14.5+ 走 Siri 后端国内可用；不支持的环境（微信内置等）降级提示。

**14. 识别文本回填 vs 直接发送**
- 选择：回填输入框供确认后发送（任务书默认方案）。误识可改可删，对中文同音词误识的容错远好于直接发送。

## T10 · 联网搜索

**15. 移植路线**
- 备选：A. 移植 Python MCP stdio 客户端；B. 扒 MCP 包源码直调底层 HTTP。
- 选择：B。Vercel 无 Python 运行时跑不了 MCP 子进程；底层就是 `POST /v1/coding_plan/search`（body {"q"}），TS fetch 直调等价、零依赖、实测连通。证据：evidence/T10/websearch-http-probe.md。

**16. 来源展示形式**
- 选择：与引用章节卡同风格的「来源」列表卡（序号+标题+域名+日期，外链新开页，协议白名单防 javascript:）；不渲染 snippet（正文已综合作答，来源卡只管溯源）；结果截前 5 条、单条 snippet 200 字防撑爆上下文。

## T7 · Memory 记忆

**17. 表结构与维度**
- 选择：每用户一行、7 个维度列（身份/阅读偏好/兴趣/聊天风格/个人事实/近期关注/待跟进）+ processed_until 进度 + updated_at。列式维度让模型增量更新有明确边界、注入时可逐维拼装。

**18. 触发时机与 serverless 保障**
- 选择：每轮回复完成后 fire-and-forget，`waitUntil` 托管（Vercel 响应关闭后实例冻结，裸 fire-and-forget 永远跑不完）；攒 4 条新消息才真正调模型（processed_until 进度，与压缩器同思路）；入口延时 3.5s 等前端把本轮问答 persist 上云。实测有/无记忆 TTFB 差 <1s，客户端零感知。

**19. 防膨胀**
- 选择：模型限每维度 ≤120 字提炼 + 写库前硬截 300 字双保险；解析失败不推进进度（与「模型判定无需更新」区分），留待下轮重试。

## T9 · 限流

**20. 新阈值**
- 选择：登录 20 次/分 + 200 次/时（参考值采纳：真实读者连续追问不应被打断）；游客收紧为 8 次/分 + 40 次/时（无身份约束按 IP，防脚本滥刷烧 token）。实测恰在阈值触发（21 次/9 次出现 429）。

## T1 · 审查与安全

**21. 数据库授权面收紧范围**
- 选择：anon 各表仅留 SELECT + search_logs INSERT；authenticated 用户数据表仅 DML（RLS 限行）、profiles 收至列级 UPDATE(nickname,bio,avatar_seed,avatar_url)；维护函数 EXECUTE 仅 service_role；默认授权改为新表仅自动授 SELECT。攻击路径实测 7/7 被拒。
- 保留例外：`increment_read_count` 对游客开放（「游客也计阅读量」是产品口径；read_count 仅展示用，刷量风险接受）。

**22. 注销账号的头像清理失败策略**
- 选择：清理失败不阻断删号（孤儿文件好过删号失败），记录日志。

**23. 兜底补卡的「承诺」判定**
- 见决策 9；另：web 来源卡计入 emittedCard（漏计曾导致联网问答被误补荐书卡）。

## 新一轮全面 Review（2026-06-12，压缩后指令：全面修 bug + 大师级优化）

**26. 审查方法论（沿袭并加密）**
- 7 路并行只读审查代理（文件域隔离：智学服务端主链/服务端异步任务/智学前端/状态数据层/阅读器/书库播放器/乱翻我的壳），逐行通读 + 宁缺毋滥确证制；全部发现由主线逐项亲自核实后才动手。共确证 5 P0 + 12 P1 + 30 余 P2，分 6 批修复提交，每批 tsc + 对应回归套件全绿后才进下一批。

**27. demo 体验账号防护边界**
- 选择：前端拦截改密/注销入口 + 删号 API 服务端 403 兜底。改密的服务端纵深防御需要 Supabase Auth Hook（控制台配置项，零人工介入约束下不可达）——技术上知道密码的人仍可直调 Auth 端点改密，记录为已知限制，后续在控制台配置 before-user-updated Hook 补齐。

**28. 真实播放覆盖口径升级**
- 选择：会话内「区间并集」去重 + 跨会话以已存覆盖为只增基线。彻底口径（持久化区间集合）需 media_progress 加列，收益不及改造成本，延后；现口径已杜绝「会话内反复重听刷已读」。

**29. 删除类操作统一「即删 + 4s 撤销」**
- 选择：我的笔记/阅读历史/阅读器划线两处全部接 toast 撤销（基建已被收藏使用）；放弃为每处加二次确认弹层（交互更重、代码更多）。书评删除保留既有二次确认（内容创作重量级，删除前确认更稳妥）。

**30. 重叠划线从「拒绝」改「并集合并扩展」**
- 选择：扩选既有划线即删旧+并集新建（想法合并、用新选颜色）。这是对「高亮交互更易用优雅」诉求收益最大的一项；配合 applyHighlights 重叠裁剪渲染与登录回调内复查，幽灵笔记三个来源全部封死。

**31. 旧验证脚本过期断言升级（非回归）**
- verify-stream-ui（"卡片只随收尾出现"是交错渲染前的旧口径）、verify-agent-context（API 已默认 NDJSON 需 stream:false）、verify-reader-md（划线按钮 aria-label 已改「划线·色名」）三个脚本升级到现行口径后全绿。

**32. 本轮评估后明确延后项（含理由）**
- loadUserData 八路查询/聊天合并写 RPC 化：需 DB 函数 + 迁移，当前用户量下收益小于改造风险；
- 客户端发送全量历史窗口化：服务端 compressed_until 按绝对下标对齐，窗口化需协议改造，现量级无痛点；
- flip 占位节点 spacer 虚拟化（F41）/ PWA 真实图标 / 行距三档：沿袭延后池；
- flipfeed 小时级 Cron 追平：当前用户量单批预算闸已根治收敛问题，量级上来再加密频率；
- chat 消息 content-visibility 离屏降本：点踩反馈浮层在消息容器内用 fixed 定位，paint containment 会把浮层裁掉，放弃。
